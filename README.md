# SmartCity — «Умный дом»: заявки жителей МКД в MAX

Чат-бот MAX (и API для мини-приложения), который помогает жителям многоквартирного дома решать
проблемы вместе с управляющей компанией (УК): создать заявку, собрать подписи соседей, передать
заявку в УК и отслеживать её статус до результата. Трек «Умный город».

> Бэкенд (бот + API) находится в `server/`, мини-приложение — статическая страница `server/public/`
> (карта выбора дома, регистрация квартиры, заявки), которую отдаёт тот же сервер по адресу `/app/`.
> API описан в `server/openapi.yaml`.

## Назначение

Житель в ситуации «в доме есть проблема» (шумные соседи, облупилась краска в подъезде, застрял лифт,
прорвало трубу) хочет, чтобы её решили, но сталкивается с тем, что неясно, зарегистрировано ли
обращение, кому передано и на каком этапе. Бот делает процесс прозрачным:

* житель создаёт заявку за 5 шагов прямо в чате с ботом или в мини-приложении;
* в мини-приложении житель выбирает свой дом на карте, а номер квартиры проверяется по открытым
  данным о доме (число квартир и подъезды из OpenStreetMap);
* соседи получают уведомление в чате дома и поддерживают заявку (подписывают);
* когда подписей набирается 20 % жителей дома, заявка автоматически уходит в УК;
* аварийные заявки уходят в УК сразу, без сбора подписей;
* УК берёт заявку в работу, передаёт в ответственную организацию (письмом с сформированным
  документом), закрывает или отклоняет — житель и подписавшие получают уведомление о каждом статусе.

## Основной пользовательский сценарий

1. Сотрудник УК создаёт групповой чат дома в MAX, добавляет жителей и бота — бот сразу предлагает
   выбрать дом. Если бота добавил не сотрудник, сотрудник отправляет в чат `@имя_бота /bind`
   (в групповом чате MAX бот видит только сообщения с его упоминанием, если он не администратор чата).
2. Новый житель открывает бота по ссылке или QR-коду, выбирает дом на карте (в боте или
   мини-приложении), вводит номер квартиры (проверяется по OpenStreetMap: число квартир и подъезды)
   и ФИО — можно подставить из профиля MAX одним нажатием, если житель согласен, либо ввести вручную.
   Дальше это заявка на вступление, а не мгновенная регистрация.
3. Заявка уходит председателю ТСЖ этого дома, если он назначен, иначе — всем сотрудникам УК.
   Пока заявку не подтвердили, житель видит объявления и новости дома, но не может создавать
   свои заявки и новости.
4. Председатель или сотрудник УК подтверждает заявку (`/membership_queue` или кнопки в личном
   сообщении от бота) — жителю приходит подтверждение и ссылка на чат дома, доступны все функции
   бота и мини-приложения. При отказе жителю приходит причина, и он может подать заявку заново.
5. Подтверждённый собственник может сам добавить своего съёмщика (`/add_tenant`: MAX ID + номер
   квартиры) — съёмщик сразу получает полный доступ без отдельного подтверждения; председателю
   ТСЖ приходит уведомление о новом жильце.
6. Житель нажимает «Создать заявку»: категория → описание → обычная/аварийная → срок сбора
   подписей → предпросмотр → «Отправить».
7. Бот публикует заявку в чат дома с кнопкой «Подробнее» (ведёт в диалог с ботом).
8. Сосед нажимает «Подробнее» → «Поддержать». Счётчик в чате обновляется.
9. При достижении порога (20 % жителей дома, минимум 1) заявка переходит в статус «Передана в УК»:
   автор и подписавшие получают уведомление, сотрудники УК получают карточку с кнопками действий.
10. Сотрудник УК нажимает «В работу» / «Передать в организацию» / «Сделано» / «Отклонить».
    Каждая смена статуса рассылается автору, подписавшим и в чат дома.
11. УК может назначить одного из жителей дома председателем ТСЖ (`/appoint_chairman`). УК и председатель
    ТСЖ могут публиковать в доме объявления (заголовок + текст, например «Отключение горячей воды»):
    `/announce` в боте или `POST /api/announcements`. Объявление уходит в чат дома и видно жителям
    в мини-приложении; редактировать и удалять его может тот же УК или председатель этого дома.
12. Любой подтверждённый житель дома может опубликовать новость соседям (не от УК — например,
    позвать в гости): `/news_new` в боте или мини-приложение, заголовок + текст + контакт для связи.
    Новость тоже уходит в чат дома; удалить её может автор или сотрудник УК (как модерация).

## Состав и архитектура

```
MAX (клиенты жителей и УК)
   │  long polling (dev) / webhook (prod)          HTTPS + initData (HMAC-SHA256)
   ▼                                                ▼
┌───────────────────────────── server (Node.js 20, TypeScript, ES-модули) ────────────────────────┐
│  bot/            — @maxhub/max-bot-api: команды, inline-кнопки, пошаговые сценарии, уведомления │
│  routes/         — Express 5: роутеры по темам (houses, requests, me…), собираются в routes/index │
│  controllers/    — обработчики ручек: разбирают запрос, вызывают services, формируют ответ       │
│  public/         — мини-приложение: HTML + TS (esbuild → JS), карта Leaflet (OpenStreetMap), /app/│
│  auth/           — проверка подписи initData мини-приложения                                    │
│  services/       — единая бизнес-логика: заявки, подписи, статусы, документы, почта             │
│  services/geo.ts — дом по точке на карте: OpenStreetMap (Overpass API), квартиры и подъезды     │
│  jobs/           — фоновая проверка просроченных сроков сбора подписей                          │
│  prisma/         — схема БД, миграции, seed                                                     │
└───────────────────────────────────────────┬─────────────────────────────────────────────────────┘
                                            ▼
                                  PostgreSQL (Prisma 7)
```

Бот и API используют одни и те же сервисы: заявка, созданная в мини-приложении, точно так же
уходит в чат дома и в УК, как созданная в боте.

**Модель данных:** `ManagementCompany` (УК и контакты) → `House` (дом, координаты, число квартир и
подъезды, порог подписей, чат в MAX) →
`User` (роль: `RESIDENT` житель, `UK_EMPLOYEE` сотрудник УК или `CHAIRMAN` председатель ТСЖ; дом, квартира,
владелец/арендатор; `onboardedAt` — заявка подтверждена, доступ открыт) → `MembershipRequest` (заявка на
вступление: ФИО, дом, квартира, статус PENDING/APPROVED/REJECTED, причина отказа, кто подтвердил) →
`Request` (заявка на ремонт/проблему: категория, приоритет, статус, подписи, срок) → `Vote` (подпись),
`StatusHistory` (история статусов), `ResponsibleOrganization` (куда УК передаёт заявки),
`Announcement` (объявление УК/председателя ТСЖ дому: заголовок, текст),
`News` (новость от любого подтверждённого жителя: заголовок, текст, контакт автора), `BotSession` (состояние
сценариев бота).

**Статусы заявки:** `VOTING` на сборе подписей → `SUBMITTED` передана в УК → `IN_PROGRESS` решается
/ `DELEGATED` передана в службу → `RESOLVED` сделано / `REJECTED` отклонена; `EXPIRED` — срок сбора
подписей истёк.

## Запуск

Требования: Node.js ≥ 20.19, PostgreSQL ≥ 14

```bash
cd server
cp .env.example .env            # заполнить DATABASE_URL и MAX_BOT_TOKEN
npm install
npm run prisma:migrate          # создаёт таблицы (при первом запуске спросит имя миграции — можно принять)
npm run prisma:seed             # тестовые данные: УК, 2 дома, организации, жители, заявки
npm run dev                     # бот (long polling) + API + мини-приложение на http://localhost:3000
```

Мини-приложение в браузере (без MAX): `http://localhost:3000/app/?dev=900000010` — параметр `dev` подставляет
MAX id пользователя (работает при `DEV_AUTH_BYPASS=true`; новый id создаёт нового жителя, `900000001…6` — жители из seed).

> Сертификат `platform-api.max.ru` выдан УЦ Минцифры (Russian Trusted Root CA), которого нет в системных
> хранилищах macOS/Windows и в Node.js. Поэтому скрипты `npm run dev` и `npm start` подключают
> `server/certs/russian_trusted_ca.pem` через `NODE_EXTRA_CA_CERTS`. Если запускаете иначе — задайте эту
> переменную сами, иначе бот упадёт с `fetch failed / UNABLE_TO_GET_ISSUER_CERT_LOCALLY`.

Другие команды: `npm run build` + `npm start` (прод: сборка `tsc` в `dist/` и мини-приложения в `public/app.js`),
`npm run typecheck` (сервер и мини-приложение), `npm test` (юнит-тесты),
`npm run bot:simulate` (офлайн-прогон всех сценариев бота с заглушкой MAX API — удобно проверять
логику без токена), `npm run prisma:studio` (просмотр БД).

## Работа с данными

* Пользователь идентифицируется по MAX id (из события бота или из подписанного initData) — никаких
  паролей.
* Порог подписей считается как `ceil(жители_дома × votePercent / 100)`, минимум 1; автор свою
  заявку не подписывает; повторная подпись невозможна (уникальный индекс).
* Дом появляется в базе при первом выборе на карте (`POST /api/houses`): по точке нажатия сервер
  берёт из OpenStreetMap здание с адресом, внутри контура которого точка (или ближайшее в радиусе
  40 м), число квартир и подъезды и привязывает дом к УК по умолчанию. Повторный выбор того же здания возвращает существующий дом.
* Проверка квартиры (`services/rules.ts → checkApartment`): номер должен попадать в диапазон одного
  из подъездов, а если подъезды не размечены — быть не больше числа квартир. Если о доме ничего
  не известно, номер принимается без проверки (в ответе `verified = false`). Диапазон подъезда
  главнее общего числа квартир: в открытых данных они иногда расходятся. Правило одно для бота и API.
* Все смены статусов пишутся в `StatusHistory` с автором изменения и комментарием.
* Документ по заявке (реквизиты, описание, список подписавших, история) формируется на лету
  (`GET /api/requests/{id}/document` или кнопка «Сформировать документ» у УК).
* Секреты только в `.env` (в репозитории — `.env.example`).

## Команды бота

Жителю: `/panel` меню, `/create` создать заявку, `/my` мои заявки, `/supported` поддержанные,
`/news_new` новость соседям, `/contacts` контакты УК, `/id` мой MAX id, `/cancel` отмена, `/help`.
Подтверждённому собственнику дополнительно `/add_tenant` — добавить своего съёмщика.
Председателю ТСЖ — то же плюс `/announce` объявление жителям своего дома и `/membership_queue`
заявки на вступление в свой дом.
Сотруднику УК: `/requests` заявки в работе, `/membership_queue` заявки на вступление (по всем домам),
`/add_owner`, `/remove_owner`, `/appoint_chairman`, `/dismiss_chairman`, `/announce` объявление
жителям дома, `/bind` (в групповом чате, с упоминанием бота) привязать чат к дому, `/uk_login <код>`.

## API мини-приложения

Спецификация: `server/openapi.yaml`. Авторизация: заголовок
`Authorization: MaxInitData <window.WebApp.initData>` (сервер проверяет подпись по токену бота).
Ошибки — единый формат `{ "error": { "code", "message" } }`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/dictionaries` | категории, статусы, приоритеты, допустимые переходы |
| `GET /api/me` | профиль; если заявка на вступление не одобрена — поле `membership` со статусом и причиной отказа |
| `PATCH /api/me` | подать заявку на вступление (дом, квартира, ФИО) — не даёт доступ сразу, ждёт подтверждения |
| `GET /api/houses`, `GET /api/company`, `GET /api/organizations` | справочники (дома — с координатами для маркеров) |
| `GET /api/houses/lookup?lat&lng` | здание по точке на карте: адрес, число квартир, подъезды (OpenStreetMap) |
| `GET /api/geo/search?q=` | подсказки адреса по строке для карты (Nominatim) |
| `POST /api/houses` | выбрать дом на карте: вернуть существующий или создать по зданию из OSM |
| `GET /api/requests?filter=all\|mine\|supported&status=…` | список заявок дома |
| `POST /api/requests` | создать заявку |
| `GET /api/requests/{id}` | заявка с подписями и историей |
| `DELETE /api/requests/{id}` | удалить свою заявку (пока идёт сбор) |
| `POST /api/requests/{id}/vote`, `DELETE …/vote` | поддержать / отозвать подпись |
| `GET /api/requests/{id}/document` | документ по заявке |
| `PATCH /api/requests/{id}/status` | УК: сменить статус (для DELEGATED — `organizationId`) |
| `GET /api/uk/requests` | УК: очередь заявок |
| `GET /api/announcements` | объявления дома (житель/председатель — свой дом, УК — по `houseId` или все) |
| `POST /api/announcements` | опубликовать объявление: УК (любой дом) или председатель ТСЖ (свой дом) |
| `PATCH /api/announcements/{id}`, `DELETE …` | изменить / удалить — тот же УК или председатель дома |
| `GET /api/news` | новости дома (житель — свой дом, УК — по `houseId` или все) |
| `POST /api/news` | опубликовать новость в своём доме — доступно любому прописанному жителю |
| `PATCH /api/news/{id}`, `DELETE …` | изменить / удалить — автор новости или сотрудник УК (модерация) |

## Мини-приложение

Страница `server/public/index.html` + `app.ts` (esbuild собирает его в `app.js`: `npm run build:app`, в режиме
слежения — `npm run dev:app`; `npm run dev` и `npm run build` делают это сами): без фреймворков, карта Leaflet на тайлах
OpenStreetMap, SDK MAX `https://st.max.ru/js/max-web-app.js` даёт `WebApp.initData`, который уходит
в API заголовком `Authorization: MaxInitData …`. Экраны:

1. **Карта.** Маркеры уже подключённых домов (`GET /api/houses`), поиск адреса строкой
   (`GET /api/geo/search`), кнопка «📍» — геолокация. Нажатие на здание → `GET /api/houses/lookup` →
   карточка «адрес, N квартир, M подъездов» → «Это мой дом» → `POST /api/houses`.
2. **Квартира.** Номер квартиры и ФИО (кнопка «Подставить имя из профиля MAX» — заполняет поле с
   согласия жителя, это просто имя из профиля MAX, а не подтверждённые паспортные данные) →
   `PATCH /api/me` отправляет заявку на вступление, доступ пока не открывается. Если такой квартиры
   в доме нет, ошибка показывается под полем («В доме 80 квартир (1–80), квартиры 81 нет»).
3. **Дом.** Пока заявка не подтверждена — баннер со статусом («ждёт подтверждения» или причина отказа
   с кнопкой «Подать заявку заново»), но уже видны объявления и новости дома. После подтверждения
   открываются адрес и квартира (с подъездом), форма новой заявки (категория, описание, аварийная),
   список заявок дома с кнопкой «Поддержать», форма новости соседям (заголовок, текст, контакт) и
   лента новостей со своей кнопкой «Удалить». Назначение председателя, подтверждение заявок на
   вступление и добавление съёмщика — только в боте (`/membership_queue`, `/add_tenant`).

## Известные ограничения

* Бот не может создать групповой чат — по правилам платформы чат создаёт сотрудник УК и добавляет
  бота; личные уведомления доставляются только тем, кто хотя бы раз открыл диалог с ботом.
* УК и организации — тестовые данные; интеграция с ГИС ЖКХ не реализована. Сведения о домах берутся
  из OpenStreetMap: число квартир и подъезды размечены не для всех зданий (в Казани — для
  большинства жилых домов); если данных нет, номер квартиры принимается без проверки.
* Overpass API — публичные серверы с ограничением частоты запросов, бывают ответы 429/504. Сервер перебирает
  адреса из `OVERPASS_URL` по очереди, а если все недоступны, берёт дом из Nominatim (адрес и число квартир,
  подъезды в этом случае неизвестны); если недоступен и Nominatim — API отвечает 503 `service_unavailable`.
* Официальный источник числа квартир — реестр МКД Реформы ЖКХ (`reformagkh.ru/opendata`,
  CSV по региону без регистрации, поля `living_quarters_count`, `entrance_count`, ФИАС `houseguid`);
  для пилота его можно загрузить в базу как проверку второго уровня. Данные 2ГИС о квартирах
  и подъездах доступны только по отдельному разрешению, у DaData — на платном тарифе.
* Отправка писем без SMTP имитируется (пишется в лог) — это явно сообщается в боте и в API.
* Документ по заявке формируется в текстовом формате (`.txt`), не PDF.
* Пока мини-приложение не подключено к боту в кабинете dev.max.ru, кнопка «Открыть приложение»
  ведёт просто в чат с ботом.
* В простом режиме (`DEV_AUTH_BYPASS=true`) сервер не проверяет подпись `initData` и верит id
  пользователя из SDK MAX — для MVP этого достаточно, для продакшена нужен `DEV_AUTH_BYPASS=false`.
* Docker-конфигурация ещё не добавлена.

## Остановка и повторный запуск

`Ctrl+C` в терминале с `npm run dev` — сервер снимает вебхук (если включён) и закрывает соединения.
Повторный запуск — снова `npm run dev`; состояние (заявки, подписи, незавершённые сценарии бота)
хранится в PostgreSQL и переживает перезапуск. Сброс данных: `cd server && npx prisma migrate reset`
(удаляет всё), затем `npm run prisma:seed`.
